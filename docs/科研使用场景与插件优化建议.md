# 文献检索插件的科研适用性评估与改进建议

**产品定位与判断。** 插件面向独立研究者，负责一项课题从选题到返修期间的文献发现、全文获取与转存。研究者应当能随时回答三个问题：这篇论文为什么进入我的课题？我实际读到的是哪个版本？可引用的条目和附件最终存在哪里？0.5.8 已能完成一次多源检索、批量获取开放全文和向 Zotero 转存。主要缺口出现在第二次操作：补回漏检的论文、给已有条目补附件、返修时重新检索，以及数月后找回当时采用的版本。

以一篇方法学论文为例：开题时从综述的参考文献发现预印本，设计实验时需要核对正式版及补充方法，写作时从 Zotero 引用正式版，返修时还要查该方法有无更新。四个阶段都依赖同一篇文献。课题中应保留发现路径、版本关系和附件去向；每一阶段单独建一份搜索结果，容易让这些联系消失。

评估对象为 0.5.8 版工作区源码（Git 基线 `99b2643`，2026-11-25）。以下判断依据任务执行、持久化、界面和导出代码。未对真实课题测量查全率、下载成功率或外部软件导入保真度。正式综述的检索记录参考 PRISMA-S，它要求报告各来源实际执行的检索策略、检索日期、检得记录数及去重方法。[PRISMA-S 原文](https://doi.org/10.1186/s13643-020-01542-z)

## 一、按研究任务判断适用性

| 研究任务 | 当前可以交付什么 | 使用结果时应如何解读 |
| --- | --- | --- |
| 开题与叙述性综述 | 从多个来源建立候选集，按相关度、年份或被引次数选读；用分组、任务笔记和 Markdown 整理阅读线索。 | 适合寻找术语、关键论文和下一轮检索方向。概览描述的是已保存的候选集，用它推断领域发文趋势或研究空白会受取数上限和排序影响。 |
| 医学专题检索与策略试验 | 可对 PubMed 等来源指定专用检索式，从记录回看命中的来源和检索块。默认选择十个来源，Google Scholar 是需自备 SerpAPI Key 的可选来源。 | 可用已知应命中的论文核对检索策略。涉及专业库、中文库或注册平台的课题，仍需按研究方案补检，并记录其贡献。 |
| 个人筛读与全文获取 | 可按未读、已读、纳入、排除标记单篇或一批文献，整理分组，批量获取开放 PDF 或部分来源的网页全文，并查看获取状态。 | 标题、摘要翻译和对话工具可辅助阅读与操作。全文获取失败应保留为待处理事项，尤其不能据此判断一篇报告不符合纳入标准。 |
| 写作前的文献交接 | 可向本机 Zotero 指定目录同步，或输出 RIS、BibTeX、CSV 和 Markdown。CSV 可交接标识符、命中来源、筛读状态和分组。 | 个人阅读清单可直接交接。投稿前应核对会议论文、预印本等条目的类型与出处；CSV 也无法交接尚未逐篇记录的排除依据。 |
| 已有课题的检索更新 | 可保留基准任务，另建任务重新检索，按论文标识比较新增、共有和本次未见的记录。 | “新增”表示新进入本次结果集。排序变化、来源失败或标识符补全都可能造成差异。原任务内重跑只保留历史条件和统计等元数据，无法从旧轮次恢复当时的逐篇清单。 |
| 正式综述与证据综合 | 可贡献补充检索结果，导出后进入团队的筛选和提取流程。 | 若需交付可复核的筛选流程、按研究归并的报告、偏倚风险评价或效应量数据表，当前需借助外部工具及评审人员完成。 |

## 二、现有功能中影响科研判断的四个细节

### 1. 检索块按并集合并，逐源改写会改变检索含义

同一任务内的启用检索块共享任务级来源列表。每个块分别运行，再合并命中。例如，若要找“疾病 A 患者接受干预 B”的研究，把 A 和 B 分成两个独立块，会同时纳入仅命中 A 或仅命中 B 的记录。需要交集时，应在目标数据库适用的同一条表达式内组合两个概念。块内可为指定来源覆写表达式；面板也已有部分语法差异提示。

这一点对复核漏检尤为重要。PubMed 与 Europe PMC 的适配层都透传输入，各自的提供器再附加适用条件；透传本身不能证明两库等价解释同一字段。Crossref 等来源会去除方括号字段标签和通配符，OpenReview 等还会去掉布尔词。一条带有排除条件的策略因此可能失去原意。[检索式适配](../src/search/query-adapter.ts) · [界面提示规则](../src/client/syntax.ts) · [任务执行](../src/host/tasks/runner.ts)

### 2. 任务计数从已取回的记录开始，无法据此推算数据库总命中数

任务默认页大小为 20，每个“检索块 × 来源”按两倍页大小请求，最低 10、最高 50，默认请求 40 条，实际返回可更少。面板翻页浏览已保存的记录，上游续页尚未实现。即使某库符合条件的论文有数百篇，当前轮次也只能处理其中一部分。

任务的 `rawHits` 是各源返回后、通过本地条件过滤的记录之和，跨源和跨块可重复计数；`deduped` 是身份合并后的条数；最终保存量还受合并后条件检查及任务上限影响，默认最多 1,500 篇。举例说，某源返回 40 条，其中 12 条通过条件，该次对 `rawHits` 的贡献是 12。直接把 12 或 40 填进综述的“数据库检得记录数”均缺乏依据。[取数与统计](../src/host/tasks/runner.ts) · [配置默认值](../src/search/config.ts) · [续页入口](../src/host/tasks/service.ts)

### 3. 自动去重能缩短清单，同一论文仍可能出现两次

每条记录按 DOI、PMID、PMCID、arXiv ID 的优先级选一个身份键；这些字段均缺失时，才尝试使用足够长的规范化标题与年份。例如，同一论文的记录甲含 DOI 和 PMID，记录乙只有相同 PMID，两条记录会分别按 DOI 和 PMID 分组。这会影响去重统计，也可能让已筛过的论文在任务对比中再次出现。另一方面，同题同年的记录也可能被误合并。正式综述还需区分“同一报告被重复收录”和“同一研究发表了多篇报告”，后者应保留报告间关系。[身份匹配与排序](../src/search/identity.ts) · [任务对比](../src/host/tasks/compare.ts)

### 4. 筛读状态能保存，作出决定时的依据保存不足

论文级状态记录了筛读结论和分组，文字笔记保存在任务级。长摘要写盘时仅保留前 800 个字符并加省略号。从磁盘恢复任务后，即使展开摘要，也可能缺失末段的结局或研究设计信息。对需要阅读全文再决定的报告，团队成员难以从现有台账还原当时看到的材料、决定发生在哪一阶段以及排除理由。[任务存储](../src/host/tasks/store.ts) · [筛读状态](../src/search/types.ts) · [CSV 字段](../src/host/export/csv.ts)

## 三、检索与题录质量的改进及验收

| 项目 | 改动及科研价值 | 可检验的交付标准 |
| --- | --- | --- |
| 1 | **显示并导出逐源检索记录。** 在现有步骤状态和轮次快照上，补齐实际提交的表达式、过滤参数、时间及各阶段数量。先解决研究者对当前结果的误读。 | 用含字段、通配符及年份限制的一次检索核对导出件与实际请求。分别列出上游报告总数、返回数、本地过滤后数、合并数和保存数。上游未提供总数时标“未知”；失败、限流跳过和成功零命中可区分。 |
| 2 | **支持按来源续检。** 对支持分页的来源保存游标或偏移量，记录停止原因。让研究者自行选择快速取样或继续取回。 | 用固定的多页样例在第二页中断后恢复，记录集合应与连续运行一致；达到用户上限、来源已取尽、来源无法继续三种情况均可辨认。 |
| 3 | **保留可用于筛读的摘要。** 将界面折叠与持久化分开；区分上游缺摘要、历史数据已截断和本地仅显示预览。 | 用一条关键纳入条件出现在第 800 字符之后的摘要验证，保存、重启、展开后仍能读到该条件；旧任务中无法恢复的内容有明确提示。 |
| 4 | **复核去重并允许撤销。** 使用共享标识符发现候选重复项，保留来源记录和匹配依据；标识冲突、仅标题相似、预印本与正式版进入人工复核。 | 用“共享 PMID 但 DOI 缺失”“同题同年不同 DOI”“同一研究的两份报告”分别验证。人工拆分后可找回原记录，筛读决定的归属可核查。 |
| 5 | **修正文献类型与导出字段。** 当前 RIS 固定输出 JOUR，BibTeX 固定输出 article，跨学科课题中的会议论文尤其容易被当作期刊文章。 | 选择期刊论文、会议论文、预印本各一条，检查 RIS 导入和 BibTeX 编译后的类型、作者、出处、年份及 DOI。源数据缺项时保留缺项信息。[RIS 实现](../src/host/export/ris.ts) · [BibTeX 实现](../src/host/export/bibtex.ts) |

## 四、需要补充的科研功能

| 优先场景 | 建议补充 | 研究者应能完成的操作 |
| --- | --- | --- |
| 跨库建集与课题交接 | **外部题录导入与批次溯源** | 将有权使用的专业库或中文库导出的 RIS 文件加入同一任务，填写来源、策略、检索日期，核对导入、解析失败和重复数量。保留原批次，便于更新。 |
| 综述筛选 | **逐篇、分阶段的决定记录** | 分开记录题摘初筛、全文获取和全文资格评估；可暂缓决定，排除时记录理由、评审人及时间，导出后可从汇总数追溯到具体报告。若面向团队综述，再增加双人独立判定、冲突裁决和研究与报告的关联。 |
| 从关键论文扩检 | **向后查参考文献、向前查施引文献** | 从一篇已知相关论文建立补检批次，每条新增记录保留种子论文、追踪方向、来源和日期，进入同一去重及筛读流程。 |
| 补齐未取得的全文 | **人工获取与附件归档** | 从未取得清单进入原始页面，通过机构或作者途径取得全文后关联本地文件，记录获得途径；仍未取得的报告单列，供后续跟进。 |
| 长期课题更新 | **固定基准清单与增量报告** | 保存每轮的记录标识、策略及来源执行状态；比较两轮时显示策略变化及未成功来源。先支持可靠的手动更新，再据此增加定时运行和提醒。 |

## 五、让全文下载与转存可持续用于同一课题

### 找到论文后，能补齐真正需要读的材料

当前已能合并多个开放获取地址、尝试 PDF、提供部分来源的网页全文，并对本地 PDF 做校验和缓存去重。做实验复现时，正文、补充方法和附表可能分别存放；读过网页正文，也不代表已把可离线复查的材料存入课题目录。[开放地址处理](../src/search/oa.ts) · [PDF 保存与缓存](../src/host/pdf/store.ts)

建议把记录单位从“此文有没有 PDF”扩展到“此文有哪些材料”。第一步支持把合法取得的本地 PDF 关联到题录，保存获得日期、途径、文件指纹和位置，匹配不确定时由本人确认。随后允许一篇论文挂接正文、补充材料和勘误，标明已知版本；来源未提供版本时保留“未知”。验收时选一篇带补充方法的论文，让研究者同时找回正式版正文和附录，且能解释先前读过的预印本与正式版的关系。

### 条目已经入库后，仍能补附件并核对去向

Zotero 转存已有目标分类选择、目标内查重和附件上传。当前连接器会报告附件上传失败，但只要条目保存成功，任务仍可能持久化为“已同步”。另一种情况是条目已建、移入指定分类失败。两者的补救操作不同，重新保存整条记录容易产生重复。[转存结果](../src/host/zotero/connector.ts) · [任务状态写回](../src/host/tasks/service.ts)

建议逐篇记录目标库、分类、可核实的目标条目标识，以及条目、分类、附件各自的结果。再次操作时展示“打开已有条目”“加入目标分类”或“仅补附件”等适用动作。先验证本机 Zotero 接口对已有条目和附件的读写能力；接口权限不足时，显示待人工完成的步骤及原文件位置。验收用例是先存无 PDF 的题录，次日补到 PDF，再连续执行两次转存。目标分类中应只有一个父条目和一份正确附件，重开任务后可核对。

### 返修时，能恢复上次交稿所用的材料

当前任务可以置顶，置顶任务跳过按时间和数量进行的自动清理。保留的检索轮次包含条件和统计；两个任务可以按论文标识比较。要回答“初投稿时具体保留了哪批记录、哪些 PDF 已交接”，还需要一份跨检索批次的固定清单。[保留策略](../src/host/tasks/store.ts) · [轮次记录](../src/host/tasks/rounds.ts)

建议先让个人课题能关联已有任务，在初稿、投稿或返修节点保存带日期的清单，包含逐篇标识、用途或保留理由、已读版本、相对文件路径和 Zotero 去向，并可随材料导出。更新时分列新发现的论文、旧论文的新版本和仍待获取的全文。验收时将课题目录移至另一位置，恢复投稿清单并重跑检索；研究者应能定位原附件，只处理确有变化的材料。

## 六、面向个人科研的开发次序

| 阶段 | 优先交付 | 用真实课题检验 |
| --- | --- | --- |
| 第一阶段：打通单篇文献的交接 | 支持按 DOI、PMID、arXiv ID 精确补录已知论文；保留完整摘要；允许人工关联 PDF；分开记录 Zotero 条目和附件结果。精确补录应校验返回标识，避免把关键词检索的第一条结果直接入库。 | 从一篇审稿人点名的论文开始，经历“已知标识 → 先存题录 → 后补 PDF → 打开目标条目”，核实题录、版本和附件对应，并验证重复操作。 |
| 第二阶段：让专题检索可补全、可解释 | 逐源展示实际检索式与取数边界，支持续检、外部题录批次导入、可复核去重，并从种子论文向前、向后追踪引文。 | 选本人熟悉的课题，事先列出已知相关论文。逐篇解释漏检发生在来源覆盖、表达式、取数截断还是误合并；记录补检途径。命中已知论文只用于发现缺陷，不能据此估计总体查全率。 |
| 第三阶段：让课题跨月可恢复、可更新 | 关联多次检索，保存投稿基准清单，管理版本与补充材料，导出可迁移的课题档案；用稳定的增量比较支撑后续提醒。 | 用一次真实返修演练，检查能否重建原清单、找到已引用版本、识别新增及更正记录，并将需要的附件补到原分类。 |

下一版宜先完成第一阶段，并把“每源实际取回多少、是否还有后续结果”提前展示。验收优先看三个可观察结果：已知标识能否定位正确论文；稍后补到的 PDF 能否进入既有条目；中断并重开后能否准确列出尚缺材料。双人仲裁、偏倚风险评价、统计合并和写作排版可交给下游工具；插件以可追溯的检索记录、准确的题录和可找回的原文为这些环节提供输入。
