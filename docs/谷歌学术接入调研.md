# 谷歌学术（Google Scholar）接入调研

> 调研日期：2026-11-13
> 结论先行：**Google 不提供官方 Google Scholar API**，且其帮助文档与条款明确要求自动化访问遵守 `robots.txt`、不提供批量访问。直接抓取属于违反服务条款的高风险做法，本插件不应内置。若要接入，只能走**第三方商业 API 且由用户自备密钥、默认关闭**的可选数据源方案。

## 1. 官方 API 情况

| 项目 | 结论 |
|---|---|
| 官方公开 API | 无。没有 endpoint、没有 API Key 申请流程、没有官方文档 |
| 开发者计划 / OAuth | 无 |
| 批量数据导出 | 不提供（官方帮助明确说明无法批量访问） |
| 官方抓取许可 | 仅允许遵守 `robots.txt` 的抓取；Scholar 检索路径在 `robots.txt` 中受限 |

Google Scholar 的帮助页面对「程序批量下载」的答复是：请在使用自动化软件访问 Google Scholar 时遵守我们的 `robots.txt`。这意味着：

- 不存在“申请一个 key 就能合法调用”的路径；
- 高频自动化访问会被 CAPTCHA 拦截、返回 429，甚至封禁出口 IP；
- 结果页 HTML 结构不承诺稳定，任何自建解析器都会随页面改版失效。

## 2. 条款与合规风险

1. **Google 服务条款**：禁止未经许可通过自动化手段访问其服务（general Google Terms of Service）。
2. **Google Scholar 帮助**：要求自动化访问遵守 `robots.txt`，且不提供批量访问。
3. **数据再分发**：Scholar 索引的内容来自出版商、机构库，各自有再利用条款；把结果落库、再分发风险更高。
4. **技术对抗**：CAPTCHA、IP 封禁、限流是常态，不是偶发。

因此：

- **直连抓取（自建 parser / `scholarly` 之类的库）不可取**，既不稳定也不合规。
- 若产品确实需要 Scholar 数据，行业通行做法是购买第三方 SERP API，由第三方承担抓取与合规责任。

## 3. 第三方方案对比

| 方案 | 形态 | 费用 | 需要密钥 | 合规责任 | 稳定性 | 备注 |
|---|---|---|---|---|---|---|
| **SerpAPI（`engine=google_scholar`）** | 托管 SERP API，返回结构化 JSON | 免费 250 次/月；Starter $25/月 1000 次 | 是 | 由 SerpAPI 承担抓取（其提供 US Legal Shield） | 高，字段有文档 | 最省事，推荐作为唯一接入方式 |
| SearchApi.io | 托管 SERP API，含 `google_scholar` 引擎 | 付费、按次 | 是 | 第三方 | 高 | 作为 SerpAPI 的备选 |
| ScrapingBee / Bright Data 等 | 通用抓取代理 | 付费 | 是 | 需自行解析、自行承担 | 中 | 仍要自己写 parser，不推荐 |
| `scholarly`（Python）/ 自建 requests+parser | 直连 scholar.google.com | 免费 | 否 | **由使用者承担** | 低（CAPTCHA、改版） | 违反 ToS，不建议 |
| 学术替代源（非 Scholar） | 官方开放 API | 免费 | 多数不需要 | 明确允许 | 高 | 见第 6 节 |

SerpAPI 免费额度为 **250 次/月**，付费从 **$25/月 / 1000 次** 起；`num` 单次最多 20 条，翻页用 `start` 偏移。

## 4. 与项目硬性约束的冲突

`AGENTS.md` 要求：

> 只接入无需付费、无需申请密钥、允许程序化访问的 API。

Google Scholar 三条全部不满足：

- 无官方 API → 不存在“允许程序化访问”的官方许可；
- 走第三方 → 需要付费与密钥；
- 直连抓取 → 违反条款。

因此它**不能作为默认免费源**并入现有 7 家。可行的定位只有一种：

> **可选数据源（opt-in）**：用户自行配置第三方密钥后启用；未配置时不出现在默认数据源中，也不参与检索。

这也意味着需要同步修订 `AGENTS.md` 中「免费数据源」的表述，为“可选付费源”留出例外说明。

## 5. 推荐接入方案（SerpAPI 可选源）

### 5.1 数据源能力

| 字段 | 取值 |
|---|---|
| `id` | `googlescholar` |
| `label` | Google Scholar |
| `homepage` | https://scholar.google.com |
| `capabilities` | abstract ✅（snippet，常被截断）、citationCount ✅、openAccess ⚠️（仅能从 resources 推断 PDF）、pdf ✅（部分） |
| `rateLimit` | 1 req/s 自限；受第三方套餐配额约束（免费 250 次/月） |
| `syntax` | 自然语言；支持引号短语、`author:`、`source:`；不解析 PubMed 字段标签 |
| `optionalKey` | 是（SerpAPI key） |

### 5.2 请求

```
GET https://serpapi.com/search.json
  ?engine=google_scholar
  &q=<query>
  &num=20
  &start=<offset>
  &hl=en
  &as_ylo=<yearFrom>
  &as_yhi=<yearTo>
  &api_key=<serpApiKey>
```

- 单页上限 20 条；`limit > 20` 时按 `start=0,20,40…` 翻页，并保持 ≥1s 间隔。
- `as_ylo` / `as_yhi` 可直接下推年份，是少见的“年份可下推”源。
- 无 OA 过滤参数，OA 只能后置筛选。

### 5.3 字段映射（SerpAPI → `PaperRecord`）

| `PaperRecord` | 来源 |
|---|---|
| `source` | `'googlescholar'` |
| `sourceId` | `inline_links.versions.cluster_id`，缺省用 `result_id` |
| `ids` | 全部为空串；仅当 `link` 含 `doi.org/` 时提取 DOI（Scholar 结果普遍不给 DOI/PMID） |
| `title` | `title` |
| `authors` | `publication_info.authors[].name`；缺失时从 `publication_info.summary` 按 `-` 前段切分 |
| `year` | 从 `publication_info.summary` 中匹配 4 位年份；失败为 `null` |
| `venue` | `publication_info.summary` 末尾 ` - <host>`；缺失为空串 |
| `doi` | 见 `ids.doi` |
| `url` | `link` |
| `abstract` | `snippet`（注意：以 `…` 结尾表示被截断） |
| `language` | 缺省 |
| `citedBy` | `inline_links.cited_by.total`，缺失为 `null` |
| `openAccess` | `resources` 中存在 `file_format === 'PDF'` |
| `pdfUrl` | 第一个 `resources[].file_format === 'PDF'` 的 `link`，否则空串 |
| `type` | 空串（Scholar 不提供类型） |

**关键限制：身份识别弱。** Scholar 不给 DOI/PMID，`identityKey` 会回落到“标题 + 年份”键，与 PubMed/Crossref 的合并率低于现有数据源；同一论文可能出现重复条目。可选的增强是命中后异步用 Crossref 按标题回查 DOI，但会额外增加请求，首版不做。

### 5.4 与其他模块的衔接

| 位置 | 改动 |
|---|---|
| `src/search/types.ts` | `SOURCE_IDS` 增加 `googlescholar`（放在末尾，避免影响既有展示顺序） |
| `src/search/providers/googlescholar.ts` | 新建 Provider，使用 `limitedJson` 走队列与健康记录 |
| `src/search/providers/index.ts` | 注册 |
| `src/search/rate-limit.ts` | `BASE_INTERVALS.googlescholar = 1000` |
| `src/search/identity.ts` | `RRF_WEIGHTS.googlescholar ≈ 0.95`（覆盖广但摘要与元数据质量一般） |
| `src/search/query-adapter.ts` | 去字段标签；`author:` / `source:` 保留；布尔词降级为空格 |
| `src/client/syntax.ts` | 加入 `NATURAL_ONLY_SOURCES` |
| `src/client/locales.ts` | `source.googlescholar`：`谷歌学术` / `Google Scholar` |
| `src/index.ts` / `config.ts` | 新增 `serpApiKey`（secret，只回传布尔值）；未配置时该源视为不可用 |
| 设置页 | 增加 “SerpAPI 密钥” 输入与配额提示；`/health` 返回 `keys.serpapi` |

### 5.5 运行行为

- **未配置密钥**：`/health` 中该源标记为不可用；`defaultSources` 不含它；若调用方显式指定，返回 `SourceStatus.skipped = true`，`note = '未配置 SerpAPI 密钥'`，不计失败。
- **密钥无效（401/403）**：`SourceStatus.error = 'SerpAPI 密钥无效'`。
- **配额耗尽 / 429**：按 `SourceSkipped` 处理，中性提示，不计失败。
- **abort / timeout**：沿用现有 `limitedJson` 的取消与重试逻辑。
- **不在本地做结果持久化之外的再分发**，导出功能沿用现有用户主动导出。

### 5.6 成本与配额控制建议

- 免费额度 250 次/月，一次检索 1 次请求（>20 条才翻页），多检索式任务会快速消耗。
- 建议默认 `limit ≤ 20`，并在设置页显示“每次检索消耗 1 次配额”的说明。
- 可选增强（首版不做）：本地记录当月调用次数，接近上限时提示。

## 6. 不接入 Scholar 的替代方案

如果目标是“覆盖更全的中文/跨库文献”，以下免费源比 Scholar 更合规：

| 数据源 | 说明 | 是否需要密钥 |
|---|---|---|
| OpenAlex / Crossref / Semantic Scholar | 已在用，覆盖英文期刊与预印本 | 否 |
| CORE | 开放获取聚合，含机构库全文 | 免费注册 key |
| DBLP | 计算机领域权威书目 | 否 |
| BASE | 比勒费尔德学术搜索引擎 | 需申请（按 IP/机构） |
| scholar.archive.org（Internet Archive Scholar） | 开放获取全文检索 | 否（以官方页面能力为准） |

## 7. 决策建议

1. **推荐**：按第 5 节实现 `googlescholar`，定位为“可选第三方源”，由用户自备 SerpAPI key，默认关闭。
2. **不推荐**：直连 `scholar.google.com` 抓取。合规与稳定性都不可接受，且会拖累整个插件的错误率与限流状态。
3. **若不愿引入付费依赖**：不接入 Scholar，改为补 CORE / DBLP 等免费源。

行为约定：

- 未配置密钥：`googlescholar` 不在默认数据源中；显式请求时按 `skipped` 处理，不算失败。
- 配置密钥后：在设置页「搜索来源」中打开「谷歌学术」开关，随后参与检索；`/health` 的 `keys.serpapi` 反映配置状态。未配置密钥时该开关不可用，服务端也会把该源从默认源中过滤掉。
- 单次检索超过 20 条会触发翻页，每次请求消耗一次 SerpAPI 配额。
